# UI : la Vertical Slice s'applique aussi aux composants Svelte

```
create-invoice/
  ui/
    InvoiceForm.svelte
    InvoiceLineItem.svelte

reconcile-bank-transaction/
  ui/
    MatchTransaction.svelte
    CreateTransactionFromBankLine.svelte
    ReconciliationSummary.svelte

shared/ui/                # composants génériques réutilisés dans le domaine (rares)

libs/ui/                  # design system générique multi-domaine (Button, Modal, Table...)
```

## Exemple concret

`libs/features/accounting/ui/src/BankStatementReconciliation.svelte` fait
aujourd'hui 80 Ko dans un seul fichier — il couvre en réalité plusieurs cas
d'usage (associer une transaction existante, créer une nouvelle transaction
depuis une ligne bancaire, afficher le résumé de rapprochement). Découpage
cible aligné sur les slices `handler` correspondantes :

- `MatchTransaction.svelte` ↔ action `match` de `reconcile-bank-transaction`
- `CreateTransactionFromBankLine.svelte` ↔ action `create` de la même slice
- `ReconciliationSummary.svelte` ↔ affichage du statut de rapprochement

Même logique pour `CheckDepositManager.svelte` (52 Ko) et
`SettingsManager.svelte` (44 Ko) : découper par cas d'usage réel de l'écran,
pas par simple taille de fichier.

## Règle

Un composant Svelte spécifique à un cas d'usage vit dans
`<domaine>/<cas-usage>/ui/`. Seuls les composants réellement génériques
(bouton, modale, table, input) vivent dans `libs/ui/`. Les apps
(`admin-console`, `boutique`) continuent d'importer ces composants via le
barrel `index.ts` du domaine — comportement déjà en place aujourd'hui
(`admin-console` importe uniquement des libs `*-ui`) à préserver strictement.
