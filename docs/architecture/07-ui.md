# UI : la Vertical Slice s'applique aussi aux composants Svelte

```
create-invoice/
  ui/
    InvoiceForm.svelte
    InvoiceLineItem.svelte

reconcile-bank-transaction/
  ui/
    reconciliation.svelte.ts             # Factory d'état réactif et méthodes métier
    reconciliation.test.ts               # Tests unitaires de la logique pure sans DOM
    BankStatementReconciliation.svelte   # Composant racine (composition & wiring, <= 300 lignes)
    ReconciliationHeader.svelte          # En-tête, sélecteur de saison et métriques
    BankTransactionsList.svelte          # Liste et filtres des lignes bancaires
    ReconciliationDetailPanel.svelte     # Panneau de détail et onglets d'actions
    ImportStatementDialog.svelte         # Modal d'importation OFX/CSV
    MatchTransaction.svelte
    CreateTransactionFromBankLine.svelte
    ReconciliationSummary.svelte

shared/ui/                # composants génériques réutilisés dans le domaine (rares)

libs/ui/                  # design system générique multi-domaine (Button, Modal, Table...)
```

## Exemple concret

`libs/domains/accounting/commands/reconcile-bank-transaction/ui/BankStatementReconciliation.svelte` est découpé selon le pattern Svelte 5 :
- `reconciliation.svelte.ts` : encapsule l'état réactif (`$state`, `$derived`), le filtrage et les requêtes HTTP `fetch`.
- `BankTransactionsList.svelte`, `ReconciliationDetailPanel.svelte`, `ReconciliationHeader.svelte`, `ImportStatementDialog.svelte` : sous-composants spécialisés.
- `BankStatementReconciliation.svelte` : composant racine léger (< 300 lignes).

Même logique appliquée sur les autres slices complexes (`CheckDepositManager.svelte`, `SettingsManager.svelte`, `ExpensesManager.svelte`).

## Découpage des composants & Règle des 300 lignes

Pour tout composant Svelte complexe de domaine :
1. **Extraction de l'état** : L'état réactif (`$state`, `$derived`) et les interactions réseau `fetch` sont encapsulés dans un fichier `[nom].svelte.ts` via une fonction factory `create[Nom]State(props)`.
2. **Sous-composants dédiés** : Le rendu visuel est découpé en sous-composants ciblés dans le dossier `ui/`. Les sous-composants reçoivent l'état via props.
3. **Limitation de taille (Principe 11 étendu)** : Tout fichier `.svelte` doit faire **au maximum 300 lignes**. Aucun fichier du dossier `ui/` ne doit dépasser **400 lignes**.
4. **Tests de Logique Pure** : La logique métier contenue dans les fichiers `.svelte.ts` est testable unitairement avec Vitest en mockant la fonction global `fetch`.

## Règle de structure

Un composant Svelte spécifique à un cas d'usage vit dans `<domaine>/<cas-usage>/ui/`. Seuls les composants réellement génériques (bouton, modale, table, input) vivent dans `libs/ui/`. Les apps (`admin`, `storefront`) continuent d'importer ces composants via le barrel `index.ts` ou `shared/ui.ts` du domaine.
